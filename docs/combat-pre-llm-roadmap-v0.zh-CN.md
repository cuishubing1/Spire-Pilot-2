# 初版 LLM Agent 接入前的战斗系统计划

## 目标

在不投入完整 C++ 模拟器开发成本的前提下，先对现有 `sts2-cli` 搜索吞吐做一次低成本优化；随后回到战斗网络，形成一个能力有限但稳定、可解释、可回退，并能被初版上层 LLM Agent 调用的 Combat Tool。

当前基线约为：复杂战斗 `45–68 simulation/s`，状态恢复与动作重放约占搜索时间的 `46%–55%`。增加 simulation 预算尚未稳定改善战斗结果，因此吞吐和模型质量需要分开处理。

## 阶段一：低投入吞吐量试验

优先尝试：

1. 继续复用常驻的 C# 游戏进程，减少进程启动与重复资源加载；
2. 在同一战斗入口批量执行多个动作前缀，减少 Python/C# 往返和 JSON 序列化；
3. 检查能否缓存或轻量复制战斗内存状态，避免每条 simulation 都从入口完整重放；
4. 对恢复、引擎 step、模型推理和协议传输分别计时，确认真实瓶颈。

验证使用固定的 Act 1、Act 2、Act 3 战斗根状态，并保证优化前后：

- 初始可见状态和合法动作完全一致；
- 相同动作前缀产生相同可见结果；
- 不读取隐藏 RNG、抽牌顺序等信息作为模型输入；
- 报告 simulation/s、恢复耗时占比和整次决策延迟。

本阶段限时约一个短迭代，不重写完整规则引擎。只有当多个代表性场景均获得至少约 `2×` 的稳定加速，且状态一致性测试全部通过时，才继续深化；理想目标为 `3×` 以上。否则保留当前真实引擎方案，停止继续优化吞吐。

## 阶段二：继续完善战斗网络

吞吐试验结束后，重点不再是盲目增加搜索次数，而是提高候选动作的价值排序质量：

1. 使用人工轨迹继续维持 Policy 的基本出牌能力和低成本候选缩减；
2. 用真实引擎产生少量、可复现的同根反事实结果，重点覆盖高战损、死亡、药水和特殊机制场景；
3. 优化 Value，使其分别预测死亡风险、战后生命分布、战斗轮数和资源消耗，并增加同状态候选动作的成对排序监督；
4. 建立典型失败场景的 ratchet 回归集，确保修复新问题时不破坏已解决的战斗；
5. 保留 Policy Only 作为安全回退，搜索仅在高风险、高分歧或上层要求增加预算时触发。

搜索产生的统计不直接循环作为同一步网络输入。搜索负责在线反事实比较；经过终局验证的搜索结果可以作为后续 Value/Policy 调优标签。

## 阶段三：冻结可供 LLM 调用的 Combat Tool V0.1

上层 LLM 不直接输出卡牌动作，而是给出结构化战斗约束，例如：

- 生命与药水的资源权重；
- 是否允许或鼓励使用某类药水；
- 目标优先级与需要保护的资源；
- 风险容忍度和搜索预算等级；
- 经规则适配器验证的敌人机制提示。

Combat Tool 返回：

- 最终合法动作及 Top-k 候选；
- Policy、精确引擎特征、Value 与 Directive 的评分拆解；
- 预计死亡风险、战损和资源消耗；
- 是否触发搜索、采用的预算和回退原因；
- 不确定性或需要上层重新规划的信号。

未经验证的自然语言机制描述不能直接进入网络或硬约束动作，必须先转成绑定具体实体和候选动作的结构化字段。

## 接入初版 LLM Agent 的完成门槛

战斗网络不要求达到 Spire Pilot 的最终强度，但至少应满足：

- 合法动作率为 100%，CLI 特殊选择和死亡终局可稳定处理；
- Policy Only、一步展开和触发式搜索均可通过统一接口调用并安全回退；
- Act 1–3 的未见战斗上没有明显系统性退化；
- Value 在典型高战损、死亡和药水反事实上的排序优于当前版本；
- Combat Directive 能改变资源偏好和搜索预算，但不能绕过引擎合法性；
- 在独立战斗测试和保留完整 A0 对局的连续测试中保存可复现报告。

达到这些门槛后，即可开始初版上层 LLM Agent。后续优化应由真实失败案例驱动，而不是在接入上层之前无限追求底层最优。

## 当前执行顺序

```text
吞吐 profiling 与低成本优化
→ 一致性和加速门禁
→ Value/候选排序优化
→ 典型失败回归集
→ 冻结 Combat Tool V0.1
→ 接入初版上层 LLM Agent
```

## 2026-08-17 执行状态

吞吐 profiling 与低成本并行门禁已完成：

- `restore_combat` 的协议和序列化残余仅约 `0.2–0.4 ms`，不是主要瓶颈；
- `LoadSave` 约 `1.4–1.8 ms`，Act 2/3 的8步真实动作前缀重放约 `13.5–14.1 ms`；
- 四个常驻 worker 的纯恢复吞吐达到单 worker 的 `3.48–3.61×`；
- 但四棵独立搜索树的 CUDA 端到端吞吐，在 Act 1/2/3 仅为 `2.29× / 1.89× / 1.57×`。

端到端结果没有在全部场景通过 `2×` 门槛，因此停止继续投入引擎并行和树合并。实验性多 worker
不接入实际动作选择，项目已转回 Value 排序与 Combat Tool 接口优化。

对应产物：

- `artifacts/sts2_cli_restore_stage_profile_v0.json`
- `artifacts/combat_search_parallel_throughput_v0.json`
- `tools/profile_sts2_cli_restore.py`
- `tools/benchmark_parallel_combat_search.py`

### 数据与模型阶段进展

当前派生快照已扩展到58个完整 episode、941场战斗和18,616条战斗 transition；训练、验证、
测试分别按战斗划分为752/84/105场，并保留5个完整测试 run 用于连续爬塔，Act 1–3 在三个
split 中均有覆盖。Value target、模型样本和词表均已从同一快照重建并通过验证。

CUDA P1.3 使用“人工行为预训练主干 + 18维公开引擎候选特征残差适配器”。测试集 Top-1 为
55.50%，合法动作率100%。它保留并冻结候选资源预测头，但默认 `decision_value_scale=0`，所以
未经反事实验证的候选价值不会接管 Policy；状态风险用于重新规划信号，候选资源值只作诊断。

在同一完整A0测试 run 的三个独立战斗上，新 P1 的一步展开取得3/3获胜，但总战损87，旧版
一步展开为45。这说明更低的 on-policy Value MAE 不等于更可靠的反事实排序。当前默认仍为
Policy Only；一步与 turn-boundary 搜索保持实验性，不扩大接管范围。

Combat Tool 0.2.0 已增加类型化 JSON 请求入口、checkpoint/词表/数据快照指纹，以及
`capabilities` 和 `directive_effects`。上层可以据此区分精确规则值、on-policy 诊断值、实验性
目标重排和尚未执行的搜索请求，不会把不可用能力误认为已实现。

## 2026-08-18 验证集真实引擎评测

P2、Encounter residual 及各自一步展开已在84场验证战斗上完成四分片 CUDA 测试。83场可
由四种方法共同评估；Test Subject Boss 因连续 `card_select` 的 CLI 超时被单列为
`engine_unsupported`。在共同子集上，人类总战损749；P2 Policy 为2,049（+173.57%，16死），
P2一步展开为1,816（+142.46%，12死），residual一步展开为1,784（+138.18%，12死）。

一步展开相对 P2 Policy 同根降低233点战损并净减少4次死亡，但16/83场战损恶化，且在Act 1
和A9–A10分组并未改善。因此下一阶段不扩大无条件搜索，而是从高战损、死亡和错误接管状态
建立 ratchet 集，生成终局验证的成对反事实标签，并训练 Value/搜索触发器。完整协议与结果见
`docs/combat-validation-full-p2-v0.zh-CN.md`。

### 2026-08-18 失败轨迹与分布偏移审计

已从83场共同可评估战斗中冻结30场失败 ratchet：16场 Policy 死亡、12场一步展开死亡、
22场相对人类多损失至少20 HP、4场搜索相对 Policy 多损失至少15 HP，其中3场由搜索引入死亡。
静态实体覆盖不是主要问题：失败组精确敌人组合在训练集的中位覆盖为12场，入口牌组未见卡牌
仅0.14%。偏移主要由在线复合误差形成：失败组与对照组早段尾部特征率为2.41%/2.23%，后段
扩大为11.83%/6.97%；搜索接管率也从对照组14.92%升至失败组22.53%。下一步应在训练 split
运行 P2 收集 on-policy 状态，再用共同 RNG、固定 continuation 的终局反事实生成成对排序标签，
而不是把验证失败直接并回行为克隆数据。详见
`docs/combat-failure-distribution-shift-v0.zh-CN.md`。

### 2026-08-18 训练集 On-Policy 反事实闭环

已在训练 split 上完成 9 场失败导向战斗的 CUDA 小规模闭环：P2 自己运行并采集 18 个根，对 Top-3 动作各使用 2 组共同 determinization 展开到真实战斗终局，共得到 108/108 条终局 world。7 个根具有非零动作价值差，3 个根明确推翻 P2 首选。

最早触发根的有效率为 5/9，并发现全部 3 个 P2 次优根；最高风险末期根只有 2/9 有信息量且没有推翻 P2。这表明修复重点应前移到偏移刚开始累积的状态。下一步是导出 informative roots，并在保留人工 BC anchor 的前提下训练候选成对排序头；这些终局标签估计的是冻结 continuation 下的 `Q^{P2}`，不能表述为最优动作真值。详见 `docs/combat-on-policy-counterfactual-v0.zh-CN.md`。

### 2026-08-18 反事实排序调优门禁

最早根采集已扩展到 60 场，得到 45 个有效根、22 个错误首选和 109 组成对标签。全局 129 参数候选末层可将反事实 holdout 成对准确率从 34.78% 提高到 60.87%，但人工 validation Top-1 下降 4.01 pp；严格规则门控后仍下降 0.90 pp。Encounter Embedding 局部适配只提高连续排序 loss，没有纠正错误首选，较强设置仍损失 1.50 pp。两类候选均已拒绝，默认保持 P2。

下一步改为“不可变 P2 + 独立条件 residual + 学习式接管”，并将 Policy 正确/平局根作为负样本。详见 `docs/combat-counterfactual-finetune-v0.zh-CN.md`。
