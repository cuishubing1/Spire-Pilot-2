# Combat Policy P2：接入 LLM 前的训练与遭遇适配实验

日期：2026-08-18

## 1. 当前默认模型

P2 采用两阶段 CUDA 训练：先用 14,883 个训练决策训练共享策略/价值主干，再冻结主干，
训练精确引擎候选特征适配器。当前默认 checkpoint 为：

```text
artifacts/combat_policy_p2_cuda/20260818T125348Z/model.pt
SHA-256: 4C65BEDD6EB177A2A552331217FC1D06C377287C198632179EDB8667E27A8B8D
```

P2 在 84 场验证战斗上的结果：Top-1 58.86%，Top-3 90.66%，NLL 1.078706，
逐战斗宏平均准确率 59.86%。在 5 个完整对局组成的 105 场测试战斗上，Top-1 57.20%，
NLL 1.164737，逐战斗宏平均准确率 58.30%。

## 2. 稳定 Encounter 身份

当前敌人集合不能直接作为遭遇身份：训练集 752 场战斗中有 339 场会因击杀、召唤或分裂
改变敌人集合。因此 Encounter 身份固定取该战斗第一条决策中的敌人 ID 多重集合，并在整场
战斗内保持不变。训练集中至少出现 3 场的签名进入词表；79 个高频签名覆盖 727/752 场
训练战斗，其他签名统一映射为 `<UNK>`。

在线推理时，runner 应在首次 `combat_play` 缓存 `encounter_signature`，后续通过
`state.context.encounter_signature` 传入。未缓存时只允许回退到当前敌人集合，不能作为正式
Encounter Adapter 评测结果。

## 3. 两种轻量适配器结果

### 全局 Encounter embedding

仅训练 10,368 个参数，将 Encounter embedding 加入全局状态。验证 Top-1 与 P2 相同，
但 NLL 变差，测试 Top-1 也轻微下降。该方案未通过门槛。

### Encounter 条件化候选残差 scorer

冻结 P2，只训练 75,905 个参数；遭遇向量与每个候选动作特征计算低秩残差分数，且不修改
已有资源预测头。checkpoint：

```text
artifacts/combat_policy_p2_encounter_residual_cuda/20260818T130748Z/model.pt
SHA-256: 36D372C846EF01D58217E72DCF6E8016136B29199A02E3BC20254672F038CA52
```

相较 P2：

| 指标 | P2 | Encounter residual |
|---|---:|---:|
| 验证 Top-1 | 58.86% | 58.68% |
| 验证 Top-3 | 90.66% | 90.96% |
| 验证 NLL | 1.078706 | 1.077749 |
| 验证逐战斗宏平均 | 59.86% | 59.65% |
| 测试 Top-1 | 57.20% | 57.25% |
| 测试 NLL | 1.164737 | 1.161412 |
| 测试逐战斗宏平均 | 58.30% | 58.69% |

结果是混合的：概率排序与完整测试略有改善，但验证 Top-1 和宏平均下降，A9-A10 Act 2
仍为 47.2%。因此它只保留为搜索先验实验分支，不能替换 P2 直接决策默认模型。

## 4. 训练器修复

冻结主干的适配器训练现在保持冻结网络处于 `eval` 模式，防止 Transformer 和 scorer 的
Dropout 在训练时随机变化。梯度仍可流向适配器，但其优化目标与验证推理保持一致。

## 5. 当前结论与停止门槛

现阶段不应继续堆叠更大的 Encounter 专用模块。下一步若继续该方向，应使用真实引擎在线
战斗或搜索消融，验证残差 scorer 的 NLL/Top-3 改善是否能转化为更好的搜索动作；若不能，
则保留共享 P2，并把敌人特殊机制、资源预算和搜索预算交给上层 LLM/Combat Directive。
