# 新增 A0 对局战斗错误审计 V0

日期：2026-08-17

## 评测边界

本报告使用新增的完整 A0 铁甲战士通关记录
`human-20260816T162845349Z-ae82ff8c5b7249738f0130d3cfff02b9`。该局只作为冻结模型的诊断集，
不参与本轮训练或调参。26 场战斗覆盖 Act 1/2/3 的 9/9/8 场战斗，共有 739 条 canonical、
training-eligible 的战斗决策。

HumanRecorder 原始记录正常封口，哈希链、Schema、合法动作和 rollback 验证均通过。P0、P1 和
P1 一步展开从相同的玩家可见战斗入口快照重建，并共享同一 CLI RNG 根。人类结果来自原始对局，
与重建策略并非同 RNG 的严格反事实，因此只作为能力参照。

该局后期拥有 `RELIC.ALCHEMICAL_COFFER`，7 个药水槽是合法状态。原价值标签错误来自药水使用后
槽位压缩导致 `instance_id` 改变，而不是药水数量异常。`combat-resource-targets` 已升级到 0.2.0，
改为按后继动作中的 `use_potion` / `discard_potion` 计数；本局 739 个目标与动作后缀逐条一致。

## 回合边界搜索诊断

对四个代表场景使用 Top-3 根动作、beam width 3、最多 3 个玩家动作、2 个可见牌堆确定化，
叶节点统一到下一玩家回合或战斗终止：

| 场景 | P1 | 一步展开 | 回合边界搜索 |
|---|---:|---:|---:|
| Chompers | 39 | 13 | 8 |
| 4 Exoskeletons | 0 | 15 | 2 |
| Construct Menagerie | 13 | 死亡 | 28 |
| Queen | 死亡 | 死亡 | 死亡 |

回合边界搜索能够纠正部分一步短视错误，并在 Construct Menagerie 中避免死亡；但它仍可能覆盖
本来更好的 P1 动作，也无法解决 Queen 的机制与长期价值缺口。增加搜索预算本身不是单调改进。

## 当前错误归因

1. **Policy 改进不足**：P1 与 P0 完全同轨，说明候选引擎特征尚未形成有意义的策略残差。
2. **价值排序不可靠**：一步展开执行的是精确转移，但转移后的状态由未随 P1 重训的价值头排序；
   Act 3 的恶化证明主要问题不是“引擎算错即时伤害”，而是叶节点价值估计错误。
3. **视野不一致**：把不同动作停在一步后比较，会偏好暂时好看但破坏整回合结构的动作；统一到
   回合边界后部分错误得到纠正。
4. **机制知识缺口**：Queen、Phantasmal Gardeners、The Insatiable 等场景无法仅靠当前通用网络和
   小预算搜索解决，需要可验证的机制事实、阶段目标和更谨慎的资源策略。
5. **前置选择尚未学习**：Gambling Chip 会在战斗开始前暴露可选换牌。当前受控评测固定
   `skip_select`，保证策略间公平，但不代表最优换牌，也不与人类原局的换牌严格等价。

## 对上层 LLM Agent 的接口启示

上层不应发送自由文本让战斗网络自行理解。现有 `CombatDirective V0` 已能表达生命/药水价值权重、
药水预算、目标和候选偏置及重新规划阈值。下一版应增加受约束的 `search_policy`：

- `mode`: `policy_only`、`one_step` 或 `turn_boundary`；
- `budget_class`: `low`、`medium`、`high`，由工具映射为受限预算；
- `max_wall_ms` 与 `determinizations` 的安全上限；
- `mechanic_plan_id`、阶段目标、目标优先级和有效期；
- 指令来源与置信度，未通过规则适配器验证的机制文本不得直接形成硬约束。

推荐的路由不是“Boss 一律加搜索”，而是：P1 作为默认执行策略；在高风险、高分歧或已知机制窗口
触发回合边界搜索；只有当校准后的价值优势超过门槛且不确定性足够低时，搜索才覆盖 P1。Boss 和
特殊敌人的上层指令主要负责设定资源预算、阶段目标与搜索预算，具体合法动作仍由下层工具决定。

## 固定局外计划的连续结果

连续 runner 使用相同 Seed 和记录中的路线、抓牌、事件计划，但战斗结果和 RNG 消耗由当前引擎
重新产生，因此实际敌人序列不保证与人类原局一致。所有战斗状态和 HP 会真实继承。

| 策略 | 最远楼层 | 完成战斗 | 结局 |
|---|---:|---:|---|
| P1 Policy | 14 | 7 | Phrog Parasite 战死亡 |
| P1 + 一步展开 + P1 回退 | 17 | 9 | Vantom Boss 战死亡 |

搜索增强版本执行 150 个战斗决策，改写 P1 动作 46 次。第 8 层由未知节点转入的战斗无法在独立
CLI worker 中重建；runner 在首次 `restore_combat` 失败后熔断该场搜索，后续 13 个动作使用 P1，
并在下一场重新启用一步展开。最终报告记录 `search_restore_failures=1`、`search_fallbacks=13`，没有
runner 阻塞或真实战斗动作拒绝。

该结果说明不稳定的一步价值排序在独立战斗中可能恶化，但在这一次连续轨迹上仍将死亡点从第14层
推迟到第一幕 Boss。它仍未通关 Act 1，且以 7 HP 进入 Vantom，因此不能据此宣称搜索整体可靠。

## 连续轨迹高战损动作审计

对 `P1 + 一步展开 + P1 回退` 的第14、15、17层逐回合检查后，主要问题不是即时伤害计算错误，
而是叶节点排序、时间边界和搜索深度不同造成的误判。

1. 第14层 Phrog Parasite 第7回合，玩家25 HP，三只 Wriggler 中两只各攻击8。手中仍有两张0费
   Anger；P1希望继续出 Anger，一步搜索却以仅0.016的策略概率提前结束回合。CLI精确分支已经计算
   `end_turn` 会立即损失11 HP，但状态价值头把该分支死亡概率估为0.055，而继续攻击分支约为0.395，
   因而错误覆盖P1。这是不同时间边界的状态价值失准，不是引擎伤害近似。
2. 第15层第3回合，Shrinker Beetle 与 Fuzzy Wurm Crawler 合计攻击24，手里只有一张10格挡的
   Defend。三费攻击加0费 Anger可以击杀19 HP的 Beetle并仅承受另一只敌人的攻击；实际序列加入
   Defend后将 Beetle 留在1 HP，承受14伤害。修复需要在同一回合内比较完整动作组合，一步展开无法
   看见“多打一张牌才能完成击杀”的联合收益。
3. 第17层 Vantom 第3回合以5 HP面对26点攻击，手中最大单卡格挡16且无法斩杀171 HP的Boss，
   已是由此前累计战损形成的不可挽回状态，不能归因于该回合某一张牌。
4. 原搜索在Vantom第一回合尝试使用 Gambler's Brew 时进入尚未支持的选牌子决策，随后把
   `discard_potion` 当作普通可比较候选并覆盖P1。搜索现在禁止主动引入丢弃药水；若P1本身选择丢弃，
   动作仍保持合法可执行。

据此加入保守的一步搜索接管门禁：搜索不能主动丢药，也不能在精确分支已经产生即时HP损失时从
出牌强行切换到 `end_turn`。药水使用没有被统一禁止。一次“要求药水必须具有至少0.02 P1概率”的
消融反而使Phrog Parasite战第二回合多承受8伤害并在第14层死亡，证明低概率弱化药水在稀疏人类
数据下仍可能是必要动作；该阈值因此默认关闭，只保留为未来上层资源指令可调参数。

门禁版本把Phrog Parasite战后HP从17提高到20，但后续战斗抽牌序列随RNG消耗改变，在第15层死亡。
这说明单条连续轨迹适合发现错误，不能单独证明总体提升。下一项应实现“高可见威胁触发的回合边界
搜索”，并在冻结的独立战斗集合上评估后再重新运行整局。

## 自适应回合边界搜索结果

新增高威胁触发器：当基于可见意图精确计算的回合结束掉血不少于8，并且达到当前HP的40%时，
该决策从一步展开升级为回合边界搜索；其余状态继续使用一步展开。第一次运行触发22个高威胁决策，
展开752条路径，把第15层 Shrinker Beetle + Fuzzy Wurm Crawler 从原先战后7 HP改善为战后26 HP，
并让Agent以26 HP而不是7 HP进入Vantom。

该运行同时暴露两个必须由引擎事实覆盖学习价值的缺陷：

- Gambler's Brew产生的 `card_select` 中间态曾被当作“到达下一回合”的有效叶节点。修复后，只有真正
  到达下一玩家回合、战斗奖励或游戏结束的分支能参与排序。
- Vantom第6回合，P1首选24格挡的Flame Barrier并可确定存活；搜索曾因状态价值头给该存活状态
  预测0.992死亡概率，反而选择引擎确认立即死亡的Bash分支。现已加入精确死亡否决：存在所有
  determinization均存活的候选时，所有determinization均由引擎确认死亡的候选失去排序资格。

修复后Agent在Vantom第6回合正确选择Flame Barrier并存活，最终在第7回合以16 HP面对28攻击、
手中最大仅10格挡时死亡。该状态本身已不可挽回。进一步检查发现第14层第一回合曾在无攻击意图时
消耗Block Potion；因此一步搜索现在不会主动选择“当前无可见承伤、没有保留格挡机制”的临时格挡
药水。该规则能保留药水，但会改变后续战斗的RNG和资源使用，单条连续轨迹仍在第17层死亡，不能
据此声称总体胜率提升。

截至本轮，最可靠的结论是：自适应回合边界搜索明显修复了多动作斩杀与高威胁防御问题；搜索叶节点
必须接受边界有效性和精确死亡硬门禁；跨战斗药水价值仍不能由单场战斗价值头独立解决，需要上层资源
预算或跨战斗价值信号。
