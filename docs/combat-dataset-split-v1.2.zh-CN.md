# Combat Dataset V1.2 划分

## 目的

V1.2 同时服务两类实验：训练和验证需要尽量利用有限的人工战斗；最终测试需要保留可从开局
连续重放的完整对局。因此采用混合粒度划分，而不是让三个 split 都按战斗随机拆分。

## 规则

1. `test_run_ids` 在 `config/combat_dataset_v1.json` 中显式冻结。
2. 测试 run 的全部合格 Act 1–3 战斗只进入 test，禁止进入 train 或 validation。
3. 排除测试 run 后，其余战斗按 `combat_id` 分组，并按 `Act × 战斗难度档` 分层后分别以
   90%/10% 分配 train/validation。
4. 战斗难度档固定为 `A0–A7`、`A8`、`A9–A10`。A8启用敌人生命/部分防御修正，A9进一步
   启用攻击/动作数值修正；A10的额外Act 3 Boss属于局级流程，不改变给定战斗的敌人数值。
5. 普通增量构建保留已有 split，只将新增非测试战斗补到对应 `Act × 难度档` 当前最缺少的集合。
6. 当一个 `Act × 难度档` 至少有6场战斗时，验证器要求train和validation都必须覆盖该层。
7. 只有显式修改测试 run 或划分契约时才使用 `--rebuild`。

## 当前规模

| Split | 战斗 | 决策 | Act 1/2/3战斗 |
|---|---:|---:|---:|
| Train | 752 | 14,883 | 316/233/203 |
| Validation | 84 | 1,670 | 35/26/23 |

按战斗难度档，train/validation分别为：`A0–A7 = 594/65`、`A8 = 18/3`、
`A9–A10 = 140/16`。A8的3场validation分别来自Act 1、2、3，修复了旧划分中A8全部进入
train的问题。

验证器同时检查：战斗不跨 split、配置中的测试 run 全部且仅属于test、测试run覆盖三个Act、
每个足量的 `Act × 难度档` 同时覆盖train/validation、进阶等级与难度档映射一致、满足完整
上下文/通关/楼层约束，以及模型样本不存在非法标签或隐藏字段。模型评估额外输出
`per_combat_difficulty_tier` 与 `per_act_combat_difficulty_tier`。
