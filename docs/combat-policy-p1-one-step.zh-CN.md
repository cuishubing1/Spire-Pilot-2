# Combat Policy P1 与一步引擎展开

Combat P1 的目标是把“能由公开引擎状态精确给出的量”直接用于候选筛选，并用真实引擎后继
状态代替缺少反事实监督的动作资源预测。它仍然只使用玩家可见信息，不读取 HumanRecorder 的
`audit_state`、真实隐藏牌序或未来 RNG。

## P1 候选特征适配器

P1 在 P0 的状态、来源实体、目标实体和动作类型表示之外，为每个合法候选增加18维显式特征：

- 当前能量、实际费用和 X 费标志；
- 实际格挡、出牌后的公开格挡量；
- 对具体目标的每击伤害、攻击次数和总伤害；
- 目标生命、格挡、出牌后剩余生命和是否斩杀；
- 当前可见总攻击、结束回合承伤、加入当前候选格挡后的承伤；
- 使用药水、丢弃药水和结束回合标志。

这些特征来自 `candidate_preview_features` 和当前敌人意图。它们描述当前公开规则结果，不预测
抽牌、随机生成、触发链或未知意图。

P1 从 `combat_policy_value_v2/20260815T125355Z` 初始化。P0 主干、候选评分器和状态 Value
全部冻结；新增特征通过初始为0的残差门控接入，只训练2,689个参数。这样训练开始时 P1 与
P0 Policy 完全一致，变化可以归因于新特征通道。

测试集结果：

| 指标 | P0 | P1 |
|---|---:|---:|
| NLL | 1.0878 | 1.0705 |
| Top-1 | 57.82% | 57.67% |
| Top-3 | 89.83% | 90.53% |
| Act 1 Top-1 | 60.85% | 60.00% |
| Act 2 Top-1 | 57.83% | 60.00% |
| Act 3 Top-1 | 54.20% | 52.42% |

P1 改善了概率 NLL 和 Top-3 覆盖，但没有改善总体 Top-1，因此它当前适合作为一步展开的候选
筛选器，尚不能仅凭离线指标替换 P0。

## Top-k 一步展开

每个真实 `combat_play` 决策执行：

1. P1 Policy 对完全等价的卡牌实例合并概率后选择 Top-3 语义候选；在可见攻击穿透当前格挡时，为合法防御牌保留一个席位；
2. 从同一战斗入口和真实动作前缀恢复当前公开根状态；
3. 仅从可见抽牌堆多重集合生成两个牌序 determinization；
4. 每个候选在相同的两个世界中分别由 sts2-cli 执行一步；
5. 精确记录即时生命、能量、格挡、敌人生命、药水和回合变化；
6. 对仍在战斗中的后继状态使用独立 `V(s')` 估计剩余资源结果；
7. 使用均值与下尾风险各50%的分数，加小幅 Policy 对数先验后选择。

规划器只有在价值优势至少为0.02时才覆盖 Policy。若覆盖动作是 `end_turn`，而 Policy 仍希望
执行其他动作，则优势必须至少为0.15，防止部分可观测 Value 因微小误差浪费剩余行动机会。

涉及 `card_select` 的候选暂不参与覆盖，因为其完整后继状态需要继续解决子决策。

## 首轮受控真实战斗

使用三个固定Seed、三个代表性A0场景。每组的牌组、遗物、药水和生命来自对应Act人工战斗
快照；Policy与一步展开从相同入口独立执行完整战斗。表中为 `一步展开掉血 - Policy掉血`，
负数代表改善。

| 场景 | Seed A | Seed B | Seed C | 平均 |
|---|---:|---:|---:|---:|
| Act 1 Fuzzy Wurm Crawler | 0 | -5 | 0 | -1.7 |
| Act 2 Bowlbugs | 0 | -26 | -28 | -18.0 |
| Act 3 Scrolls of Biting | -44 | -57 | -18 | -39.7 |

9/9 个 Policy 和一步展开分支均通关。全部189个一步决策的中位耗时约207 ms，平均约247 ms，
95分位约673 ms。该速度已经适合继续做离线和受控战斗评测，但还没有进行并行 worker 优化。

正式有效报告为：

- `artifacts/combat_one_step_determinized_seed_a.json`
- `artifacts/combat_one_step_determinized_seed_b.json`
- `artifacts/combat_one_step_determinized_seed_c.json`

更早的 `combat_one_step_act*`、`combat_one_step_seed_*` 和 `combat_one_step_gated_*` 是开发期
固定真实隐藏牌序的接口测试，违反正式玩家可见评测边界，不用于任何效果结论。

## 当前边界

- 只有每个Act一个普通战斗和三个Seed，不能证明对精英、Boss或未见机制泛化；
- 两个 determinization 只处理抽牌堆不确定性，尚未系统覆盖随机生成卡牌和随机目标；
- 状态 Value 来自有限的人类轨迹，在分布外后继状态上仍可能系统性误估；
- 药水动作测试集仍为0/18，P1没有解决药水监督稀疏问题；
- 一步展开不是完整 MCTS；它验证的是“Policy缩小候选 + 真实一步转移 + 状态Value”的低成本路径。

因此当前结论是：Combat P1 已通过实现与小规模真实引擎门禁，下一阶段应扩大版本化战斗场景
集并检验优势门槛，而不是立即把它声明为默认强策略或生成搜索教师标签。
