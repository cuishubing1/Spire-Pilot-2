# 训练集 On-Policy 终局反事实闭环 V0

## 目标

验证集失败审计表明，当前 P2 的主要问题不是入口状态含有大量未见实体，而是行为克隆策略在真实执行后逐步进入训练分布尾部。为避免把验证集错误回灌进训练，本闭环只在 `train` split 重建战斗，并让冻结的 P2 Policy 自己运行，从其实际访问的状态中采集候选根。

## 数据生成协议

每场战斗执行以下步骤：

1. 使用公开战斗入口、玩家可见状态与合法动作重建训练集战斗；
2. 由冻结 P2 Policy 在线执行，记录低血量、可见即时承伤、策略高熵、低 margin、罕见动作和超出训练轮数分布等触发信号；
3. 每场选择一个最高风险根和一个最早触发根，避免全部样本集中在战斗末期；
4. 对 Policy Top-3 动作使用相同的玩家可见抽牌 multiset 和相同 determinization；
5. 执行候选动作后，统一使用冻结 P2 argmax continuation，直到真实引擎返回战斗终局；
6. 记录死亡、终局生命、战损、药水消耗、最大生命变化、效用及同 determinization 的成对偏好。

所有隐藏 RNG 和真实抽牌顺序仅用于引擎内部展开，不作为网络输入。`card_select` 暂时使用确定性第一个选项，并在产物中显式标记。

## 2026-08-18 CUDA 小规模结果

使用 Act 1/2/3 轮转、优先覆盖验证失败敌人的 9 场训练战斗：

```text
战斗数                         9
P2 高战损或死亡战斗            9
反事实根                       18
Top-k                          3
每动作 determinizations        2
真实终局 world                108 / 108
具有非零动作价值差的根          7 / 18
P2 首选动作被终局标签推翻的根    3 / 18
总墙钟时间                     92.23 s
```

按根的选择位置拆分：

| 根类型 | 有信息量 | P2 次优 |
|---|---:|---:|
| 最高风险根 | 2/9 | 0/9 |
| 最早触发根 | 5/9 | 3/9 |

这说明等到低血量或战斗末期再采样，常常只会得到“所有动作都死亡”或“所有动作都立即胜利”的平局。更有用的监督出现在错误开始累积的早期状态。

三个已发现的可纠正根包括：

- Soul Nexus 开局：P2 首选升级 Rampage；在两组共同 determinization 中，True Grit 的平均终局战损少约 6.5 HP；
- Lagavulin Matriarch 第 2 回合：Rampage 的平均效用高于 P2 首选 Cinder，而 Fiend Fire 会把后续推向死亡；
- Frog Knight 开局：Defend 的平均终局战损比 P2 首选 Feel No Pain 少约 6 HP。

产物位于 `artifacts/combat_on_policy_counterfactual_v0.json`，该目录被 Git 忽略。

## 证据边界

这些标签是共同隐藏信息假设下、真实引擎终局验证的 `Q^{P2}(s,a)`：候选第一步不同，后续都由同一个冻结 P2 执行。它们不是全局最优的 `Q*(s,a)`，也不是完整 MCTS 教师。

当前每个动作只使用两组 determinization，足以验证管线和发现明显排序错误，但不足以精确估计高随机性卡牌的期望与尾部风险。平局根仍保留审计，但不应作为“改写 Policy”的正监督。

## 修复分布偏移的训练方式

下一版训练不应丢掉人工行为克隆主干，也不应把终局标签当成唯一真值。建议：

1. 人工动作监督继续作为 Policy anchor；
2. 仅将训练 split 中 `teacher_eligible=true` 且 `informative=true` 的根加入反事实数据集；
3. 使用成对排序损失训练候选价值/残差排序头；
4. 对 `policy_suboptimal=true` 的根提高权重，对终局平局根只用于校准或不参与排序；
5. 保持冻结 P2 或人工动作的 KL/交叉熵约束，防止少量困难样本破坏常规战斗能力；
6. 训练后只在未参与采集的 validation/test 战斗上重新评估战损、死亡和搜索接管错误。

规模化前的下一道门槛是：先导出版本化的 informative-root 数据集，并完成一次“人工 BC anchor + 反事实 pairwise ranking”的小模型消融。如果验证集没有改善，停止扩大终局 rollout 数量，优先检查 continuation 偏差与根选择策略。
